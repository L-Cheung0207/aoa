# 历史记录模块详细设计

> 本文面向产品、设计、研发、测试共同理解。内容基于当前实现梳理，说明页面、字段来源、功能、业务规则和关键技术链路。文中提到的源码路径、方法名和字段名均以当前代码为准。

## 1. 模块介绍

历史记录模块用于查看和管理本机产生的语音输入记录。用户完成一次语音输入、翻译或智能改写后，如果开启了历史保存，本模块会展示对应的文本、音频和处理状态。

当前历史记录只保存在本机，不直接来自服务端接口。记录索引保存在应用用户数据目录下的历史文件中，音频保存在同目录的音频子目录中。当前实现里也存在一套本地 SQLite 语音记录表 `voice_entries`，但历史页面没有读写这张表，因此不能把它当作本模块当前数据源。

当前数据源结论：

- 历史页主数据源：本地文件 `app.getPath("userData")/history/index.json`。
- 历史音频源：本地文件 `app.getPath("userData")/history/audio/{记录编号}.wav.enc` 或旧版未加密 `{记录编号}.wav`。
- 历史保留策略源：本地配置 `settings.privacy.historyRetention` 和 `settings.privacy.saveHistory`，通过 `electron-store` 持久化。
- 当前不使用 SQLite 作为历史页数据源。SQLite 表 `voice_entries` 存在于 `packages/db/src/schema/voiceEntries.ts`，但历史页调用链没有接入 `packages/db/src/repositories/voiceEntryRepository.ts`。

### 主要入口

- 首页左侧导航中的“历史记录”。
- 托盘菜单中的“历史记录”，会打开首页并切换到历史记录区域。
- 当前实现里存在独立历史窗口的历史遗留入口，但主流程没有发现实际打开入口。此处标记为当前实现未确认。

### 2.2 历史页调用链

进入历史页后的加载链路：

1. `HistoryPage` 首次渲染时执行 `useEffect`。
2. 页面调用 `window.voiceAI.listHistoryRecords()`。
3. `voiceApi.ts` 把调用转成 `ipcRenderer.invoke("voice:list-history-records")`。
4. `ipcRoutes.ts` 中的 `listHistoryRecords()` 先执行 `pruneExpiredHistoryRecords()`，再执行 `historyStore.list()`。
5. `historyStore.list()` 读取 `index.json`，必要时迁移旧版未加密音频为加密音频，然后按 `startedAt` 倒序返回记录数组。
6. `HistoryPage` 把记录放入 `records` 状态，并在前端按类型筛选、按日期分组展示。

历史页不会直接访问 SQLite，也不会请求服务端历史接口。

### 2.3 本地存储位置和文件结构

主进程启动时在 `bootstrap.ts` 创建历史存储：

```ts
createFileHistoryStore({
  rootDir: join(app.getPath("userData"), "history"),
  audioEncryptionKey: getOrCreateHistoryAudioEncryptionKey(...)
})
```

因此实际落盘结构如下：

```text
{Electron userData}/
  history/
    index.json
    audio/
      history-xxx.wav.enc
      history-yyy.wav
```

`index.json` 结构：

```json
{
  "records": [
    {
      "id": "history-...",
      "createdAt": "2026-06-08T10:00:00.000Z",
      "startedAt": "2026-06-08T09:59:30.000Z",
      "durationMs": 30000,
      "mode": "direct",
      "status": "completed",
      "transcript": "识别文本",
      "finalText": "最终文本",
      "selectedText": "智能改写时的选中文本",
      "errorMessage": "错误信息",
      "audio": {
        "path": ".../history/audio/history-xxx.wav.enc",
        "url": "file:///.../history/audio/history-xxx.wav.enc",
        "sampleRate": 16000,
        "durationMs": 30000,
        "sizeBytes": 12345
      }
    }
  ]
}
```

`audio.path` 是本机绝对路径，页面不展示给用户。下载和重试时由主进程按记录编号查 `index.json`，再读取对应文件。

### 2.4 SQLite 表说明

当前仓库存在 SQLite 表 `voice_entries`：

| SQLite 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `created_at` | 创建时间，毫秒时间戳 |
| `raw_text` | 原始识别文本 |
| `final_text` | 后处理文本 |
| `mode` | 后处理模式 |
| `language` | 语言 |
| `app_name` | 目标应用名 |
| `window_title` | 目标窗口标题 |
| `duration_ms` | 录音时长 |
| `transcription_ms` | 转写耗时 |
| `postprocess_ms` | 后处理耗时 |
| `insert_ms` | 插入耗时 |
| `status` | `success` 或 `failed` |
| `error_code` | 错误码 |

这张表由 `packages/db/src/schema/voiceEntries.ts` 和 `packages/db/src/repositories/voiceEntryRepository.ts` 定义。当前历史页没有调用 `createVoiceEntryRepository()`，也没有使用 `voice_entries` 字段。若后续要切换到 SQLite，需要新增历史页读取、删除、保留策略清理、音频关联的迁移设计。

## 3. 页面内容与字段说明

### 3.1 页面区域

| 页面内容 | 用户看到什么 | 数据来源 | 是否可编辑 | 空值与异常规则 |
|---|---|---|---|---|
| 页面标题 | “历史记录”或对应语言文案 | 本地多语言文案，语言取自界面语言设置 | 否 | 语言缺失时使用简体中文文案 |
| 页面副标题 | 提示历史只保存在当前设备 | 本地多语言文案 | 否 | 同上 |
| 更多按钮 | 顶部右侧的省略号按钮 | 页面静态内容 | 否 | 当前没有绑定实际菜单，后续用途当前实现未确认 |
| 保存历史区域 | 询问希望保留历史多久 | 本地设置中的隐私配置 | 是 | 设置读取失败时页面显示错误 |
| 保存时长下拉框 | 从不、24 小时、1 周、1 个月、永远 | 本地设置 | 是 | 未配置时按“是否保存历史”推导，开启为永远，关闭为从不 |
| 隐私说明 | 说明记录只存储在本机 | 本地多语言文案 | 否 | 无 |
| 类型筛选 | 全部、口述、翻译、改写 | 页面内部筛选状态 | 是 | 无记录或筛选后为空时展示空状态 |
| 错误提示 | 加载、删除、下载、保存策略失败时的错误信息 | 本地操作异常 | 否 | 无错误时不显示 |
| 空状态 | “暂无历史记录”一类提示 | 当前筛选结果 | 否 | 当前没有可展示记录时显示 |
| 操作提示 | 重试失败等短暂提示 | 页面内部状态 | 否 | 自动消失 |

### 3.2 历史记录字段

| 字段 | 用户含义 | 页面展示 | 数据来源 | 规则 |
|---|---|---|---|---|
| 记录编号 | 每条历史的唯一标识 | 不直接展示，用于操作定位 | 本地历史存储自动生成 | 必须唯一，重复时自动补后缀 |
| 创建时间 | 记录写入本地的时间 | 不直接展示 | 主进程写入时生成 | 更新记录时保留原创建时间 |
| 开始时间 | 本次录音开始时间 | 行首时间、日期分组、下载文件名 | 语音会话开始时记录 | 列表按开始时间倒序 |
| 持续时间 | 本次录音持续多久 | 当前页面不展示 | 语音开始和结束时间差，重试时可由音频长度推算 | 必须大于等于 0 |
| 模式 | 口述、翻译、智能改写 | 影响筛选和按钮展示 | 语音触发入口 | 当前有三类：语音输入、翻译、智能改写 |
| 状态 | 完成、取消、无音频、错误 | 文本为空时作为兜底文案；非完成状态可重试 | 语音处理结果 | 当前异常语音流程主要进入悬浮窗错误状态，不一定写入错误历史 |
| 识别文本 | 语音识别出的原始文本 | 列表正文、答案弹窗输入区 | 语音识别服务 | 可为空，空时使用最终文本或状态文案兜底 |
| 最终文本 | 插入、翻译或改写后的文本 | 列表正文、答案弹窗答案区 | 直写模式来自识别文本；翻译和改写来自后处理结果 | 可为空，空时按状态展示 |
| 选中文本 | 智能改写时用户原本选中的内容 | 答案弹窗输入区兜底 | 主进程读取当前选区 | 仅智能改写且存在选区时保存 |
| 错误信息 | 处理失败原因 | 当前页面未展示 | 历史类型支持，但主流程暂未稳定写入 | 若后续展示，需要明确错误摘要和详情位置 |
| 音频信息 | 可下载或重试的录音文件 | 有音频时显示下载按钮；非完成记录有音频时可重试 | 本地音频文件 | 音频缺失时不显示下载，重试按钮禁用 |

| 字段 | 用户含义 | 数据来源 | 规则 |
|---|---|---|---|
| 文件路径 | 本机音频保存位置 | 本地历史存储 | 当前不展示给用户 |
| 文件链接 | 本机文件访问地址 | 本地历史存储 | 当前页面不直接使用 |
| 采样率 | 音频质量参数 | 录音模块 | 固定为 16k |
| 音频时长 | 音频长度 | 按采样点数量推算 | 可用于重试时恢复持续时间 |

### 3.4 技术字段映射

历史记录使用 `packages/shared/src/types/history.ts` 中的 `HistoryRecord` 类型。当前 `index.json` 中的记录字段与页面展示关系如下：

| JSON / TS 字段 | 类型 | 写入位置 | 页面使用位置 | 说明 |
|---|---|---|---|---|
| `id` | `string` | `historyStore.create()` 自动生成，格式类似 `history-{timestamp}-{random}` | 删除、下载、重试、事件同步定位 | 若生成值重复，`ensureUniqueId()` 自动追加 `-1`、`-2` |
| `createdAt` | ISO 时间字符串 | `historyStore.create()` 写入当前时间 | 当前页面不展示 | `historyStore.update()` 会保留原值 |
| `startedAt` | ISO 时间字符串 | `voiceOperationController` 创建会话时记录 | 列表时间、日期分组、下载文件名、排序 | 更新记录时保留原值；清理过期记录也按此字段判断 |
| `durationMs` | `number` | `emitHistoryRecord()` 用结束时间减 `startedAt`；重试时优先用 `record.audio.durationMs` | 当前页面不展示 | IPC 校验要求大于等于 0 |
| `mode` | `"direct"` / `"translate"` / `"processSelection"` | 语音入口传入 | 类型筛选、智能改写答案按钮 | 页面把 `direct` 显示为口述，`translate` 显示为翻译，`processSelection` 显示为改写 |
| `status` | `"completed"` / `"cancelled"` / `"no_audio"` / `"error"` | `emitHistoryRecord()` 或重试逻辑 | 状态兜底文案、是否显示重试按钮 | 当前主流程稳定写入 `completed`、`cancelled`、`no_audio` |
| `transcript` | `string` | ASR 最终识别结果 `finalTranscript` | 列表文本、答案弹窗输入区 | 可为空 |
| `finalText` | `string` | 直写为识别文本，翻译/改写为后处理结果 | 列表文本、答案弹窗答案区 | 可为空 |
| `selectedText` | `string?` | `processSelection` 会话中的选中文本 | 答案弹窗输入区兜底 | 只有存在选区时写入 |
| `errorMessage` | `string?` | 类型和 IPC 支持 | 当前页面不展示 | 当前主流程没有稳定写入错误历史 |
| `audio` | `HistoryAudioFile?` | 有 PCM 帧时 `historyStore.writeAudioFile()` 写入 | 下载按钮、重试按钮 | 没有音频时不写此字段 |

音频对象 `HistoryAudioFile` 字段映射如下：

| JSON / TS 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `audio.path` | `string` | `writeAudioFile()` 写入的本机绝对路径 | 主进程读取音频使用 |
| `audio.url` | `string` | `pathToFileURL(audioPath).toString()` | 当前历史页下载不直接使用 |
| `audio.sampleRate` | `16000` | 录音模块固定采样率 | IPC 校验只接受 16000 |
| `audio.durationMs` | `number` | `pcm.length / sampleRate * 1000` | 重试时用于恢复记录时长 |
| `audio.sizeBytes` | `number` | 落盘 buffer 字节数 | 加密音频时是加密后大小 |

历史保留设置字段来自 `AppSettings.privacy`：

| 设置字段 | 类型 | 存储位置 | 说明 |
|---|---|---|---|
| `privacy.saveHistory` | `boolean` | `electron-store` 的 `settings` 键 | 控制新历史是否保存 |
| `privacy.historyRetention` | `"never"` / `"24h"` / `"7d"` / `"30d"` / `"forever"` | `electron-store` 的 `settings` 键 | 控制保留周期和清理规则 |

`mergeSettingsPatch()` 会保持两个字段同步：`historyRetention === "never"` 时 `saveHistory` 为 `false`；其他保留策略下 `saveHistory` 为 `true`。

## 4. 功能点描述

### 4.1 加载历史记录

用户进入历史记录页后，页面从本机文件历史存储读取记录。具体调用链：

1. `HistoryPage` 调用 `window.voiceAI.listHistoryRecords()`。
2. `voiceApi.ts` 发送 IPC：`voice:list-history-records`。
3. `ipcRoutes.ts` 执行 `listHistoryRecords()`。
4. 主进程先调用 `pruneExpiredHistoryRecords()`，按当前 `settings.privacy.historyRetention` 清理过期记录。
5. 主进程再调用 `historyStore.list()`，读取 `index.json`。
6. 页面收到 `HistoryRecord[]` 后写入 `records` 状态。

`historyStore.list()` 的数据来源是 `index.json` 的 `records` 数组。读取时如果发现旧版未加密音频，并且当前有音频加密密钥，会调用 `migrateLegacyAudioFiles()` 把旧 `.wav` 转成 `.wav.enc`，再写回 `index.json`。

成功时，页面按 `startedAt` 倒序展示。失败时，页面把异常 message 写入 `error` 并展示。

### 4.2 实时同步新记录

历史页订阅两个本机事件：

- `window.voiceAI.onHistoryRecordCreated(callback)`：对应主进程广播 `voice:history-record-created`。
- `window.voiceAI.onHistoryRecordDeleted(callback)`：对应主进程广播 `voice:history-record-deleted`。

创建或重试更新历史时，主进程在 `createHistoryRecord()` / `updateHistoryRecord()` 成功后调用 `onHistoryRecordCreated(record)`，`bootstrap.ts` 再通过 `BrowserWindow.getAllWindows()` 广播给所有窗口。历史页收到后执行 `upsertHistoryRecord()`：同 `id` 记录先替换，不同 `id` 记录插入，再按 `startedAt` 倒序排序。

删除或保留策略清理历史时，主进程广播删除事件。历史页收到后执行 `removeHistoryRecordsById()`，从列表移除记录；如果当前答案弹窗打开的是被删记录，也会关闭弹窗。

### 4.3 筛选记录

筛选只在前端内存数组中执行，不查询后端，不改本地文件：

| 筛选项 | 判断逻辑 |
|---|---|
| 全部 | 不过滤 |
| 口述 | `record.mode === "direct"` |
| 翻译 | `record.mode === "translate"` |
| 改写 | `record.mode === "processSelection"` |

筛选函数是 `HistoryPage.tsx` 中的 `matchesFilter()`。

### 4.4 按日期分组

分组函数是 `groupHistoryRecordsByDay()`。它读取每条记录的 `startedAt`，通过 `new Date(record.startedAt)` 转成日期，再用 `toISOString().slice(0, 10)` 得到日期 key。

规则：

- 日期 key 等于当前日期 key：显示“今天”。
- 日期 key 等于当前日期减 24 小时后的 key：显示“昨天”。
- 其他情况：显示 `YYYY-MM-DD`。

当前实现没有“跨零点自动刷新分组”的专用定时器。页面已经打开且没有任何状态变化时，“今天/昨天”标签不会因为系统时间过零点自动重算；发生列表更新、设置更新、重试提示消失等重新渲染时才会按新的 `new Date()` 重新计算。

### 4.5 删除单条记录

删除链路：

1. 用户点击删除按钮，页面设置 `pendingDeleteRecord`，显示确认弹窗。
2. 用户确认后，页面调用 `window.voiceAI.deleteHistoryRecord(id)`。
3. `voiceApi.ts` 发送 IPC：`voice:delete-history-record`，参数 `{ id }`。
4. `ipcSchemas.ts` 的 `parseDeleteHistoryRecordInput()` 校验 `id` 必须是非空字符串。
5. `ipcRoutes.ts` 调用 `historyStore.delete(id)`。
6. `historyStore.delete()` 从 `index.json` 找记录；找到后从 `records` 数组移除，若有 `audio.path` 则 `rm(audio.path, { force: true })` 删除音频，再写回 `index.json`。
7. 删除成功时主进程广播 `voice:history-record-deleted`。
8. 页面移除该记录并关闭相关答案弹窗。

如果 `index.json` 中找不到对应 `id`，`historyStore.delete()` 返回 `false`，主进程不广播删除事件，页面保留原记录。

### 4.6 修改历史保留策略

用户可以选择：

- 从不：`never`
- 24 小时：`24h`
- 1 周：`7d`
- 1 个月：`30d`
- 永远：`forever`

设置保存链路：

1. 页面下拉框变化时，只设置 `pendingRetention`，不会立即写本地。
2. 用户在确认弹窗确认后，页面调用 `window.voiceAI.applyHistoryRetention(pendingRetention)`。
3. `voiceApi.ts` 发送 IPC：`voice:apply-history-retention`，参数 `{ retention }`。
4. `ipcSchemas.ts` 的 `parseApplyHistoryRetentionInput()` 校验 `retention` 必须是合法枚举。
5. `ipcRoutes.ts` 执行 `configStore.update({ privacy: { historyRetention: retention } })`。
6. `mergeSettingsPatch()` 同步 `saveHistory`：`never` 对应 `false`，其他值对应 `true`。
7. 主进程调用 `deleteHistoryRecordsForRetention(historyStore, retention, now)` 清理历史。
8. 被删除记录的 `id` 会逐个通过 `voice:history-record-deleted` 广播到页面。
9. 页面用返回的 `settings` 更新下拉框，用 `deletedIds` 移除列表记录。

清理规则：

| 保留策略 | 主进程计算 | 删除逻辑 |
|---|---|---|
| `never` | 返回 `"clear"` | `historyStore.clear()` 删除所有记录和音频 |
| `24h` | `now - 24 * 60 * 60 * 1000` | `historyStore.pruneBefore(cutoff.toISOString())` 删除 `startedAt < cutoff` 的记录 |
| `7d` | `now - 7 * 24 * 60 * 60 * 1000` | 同上 |
| `30d` | `now - 30 * 24 * 60 * 60 * 1000` | 同上 |
| `forever` | `undefined` | 不删除 |

重要业务结论：

- 当前没有历史保留策略专用的后台定时器。
- 当前没有针对 `24h` / `7d` / `30d` 的 `setInterval` 或计划任务。
- 选择“保留 24 小时”后，如果软件一直不关闭、历史页一直打开、期间也没有创建/更新历史或再次进入历史页，旧记录不会在满 24 小时时自动从页面和磁盘删除。
- 过期记录会在下一次触发清理时删除：进入历史页加载列表、创建新历史、重试更新历史、再次修改保留策略。
- 如果用户第二天打开历史页，`listHistoryRecords()` 会先清理超过 24 小时的记录，再返回列表。
- 如果用户第二天没有打开历史页，但产生了一条新历史，`createHistoryRecord()` 保存新记录后会执行清理，旧记录会被删除并广播删除事件。

### 4.7 下载音频

下载链路：

1. 页面仅在 `record.audio` 存在时显示下载按钮。
2. 点击后调用 `window.voiceAI.readHistoryAudio(record.id)`。
3. `voiceApi.ts` 发送 IPC：`voice:read-history-audio`，参数 `{ id }`。
4. 主进程调用 `historyStore.readAudio(id)`。
5. `historyStore.readAudio()` 从 `index.json` 找记录，再读取 `record.audio.path`。
6. 如果文件头是加密魔数 `VHAUD001`，调用 `decryptAudioBuffer()` 用 AES-256-GCM 解密。
7. 主进程返回 `{ data: ArrayBuffer, mimeType: "audio/wav", sizeBytes }`。
8. 页面用 `Blob` 和临时 `<a>` 触发浏览器下载。

下载文件名由 `buildHistoryAudioFileName(record)` 生成，格式为 `voice-history-{startedAt}.wav`，其中 `:` 和 `.` 会替换为 `-`。

如果记录有 `audio` 字段但文件不存在，`readFile(record.audio.path)` 抛错，页面显示错误。若主进程返回 `undefined`，页面显示“历史音频文件未找到”类文案。

### 4.8 查看智能改写答案

只有满足以下条件才显示“查看答案”：

- `record.mode === "processSelection"`。
- `record.finalText.trim().length > 0`。

弹窗内容：

- 输入区：调用 `getHistoryRecordListText()`。智能改写优先显示 `record.transcript.trim()`，其次显示 `record.selectedText?.trim()`，最后使用 `statusLabels[record.status]`。
- 答案区：显示 `record.finalText.trim()`；如果为空，使用状态文案兜底。

### 4.9 重试失败记录

页面只对非完成记录渲染重试按钮：`record.status !== "completed"`。按钮是否可点取决于 `record.audio !== undefined`，且同一时间只允许一条记录重试。

重试链路：

1. 页面调用 `retryHistoryRecord(record)`。
2. `retryHistoryRecord()` 并发读取：`readHistoryAudio(record.id)`、`getSettings()`、`bootstrapClient()`。
3. `decodePcm16Wav(audio)` 校验音频必须是 16k、单声道、PCM16 WAV，并解出 `Int16Array`。
4. `transcribeHistoryAudio()` 调用 `startTranscription()`，把 PCM 拆成 1600 采样点一帧，通过 `sendTranscriptionAudio()` 重新送 ASR，最后调用 `stopTranscription()` 得到文本。
5. `resolveHistoryRetryFinalText()` 按原记录 `mode` 处理：
   - `direct`：最终文本等于重新识别文本。
   - `translate`：调用 `postprocess()`，mode 为 `translate`。
   - `processSelection`：调用 `postprocess()`，mode 使用当前设置 `settings.ai.defaultMode`，并传入原 `selectedText`。
6. 构造新的 `CreateHistoryRecordInput`，调用 `window.voiceAI.updateHistoryRecord({ id: record.id, ...input })`。
7. 主进程 `historyStore.update()` 保留原 `id`、`createdAt`、`startedAt`，替换文本、状态、音频信息，并写回 `index.json`。
8. 更新成功后广播 `voice:history-record-created`，页面用同 `id` 记录替换旧记录。

重试失败时不会调用 `updateHistoryRecord()` 成功写入，因此原记录不被覆盖；页面只显示短暂失败提示。

## 5. 业务逻辑及规则

### 5.1 记录创建规则

历史记录由语音控制器在会话结束或取消时组装，不由历史页面主动创建。

语音会话开始时，`voiceOperationController` 创建 `ActiveSession`：

| 会话字段 | 来源 | 后续用途 |
|---|---|---|
| `mode` | 触发入口 | 写入 `record.mode` |
| `selectedText` | 智能改写入口读取到的选中文本 | 写入 `record.selectedText` |
| `startedAt` | `getNow().toISOString()` | 写入 `record.startedAt` |
| `startedAtMs` | `getNow().getTime()` | 录音时长和最大录音时长计算 |
| `audioFrames` | 录音模块持续推送的 PCM 帧 | 会话结束时拼接成历史音频 |

会话结束时，`emitHistoryRecord()` 组装 `CreateHistoryRecordInput`：

| 入参字段 | 组装规则 |
|---|---|
| `startedAt` | 使用会话开始时间 `session.startedAt` |
| `durationMs` | `endedAt - startedAt`，最小为 0 |
| `mode` | 使用会话 `session.mode` |
| `status` | 由结果决定 |
| `transcript` | 使用 ASR 最终文本 |
| `finalText` | 使用直写、翻译或改写后的最终文本 |
| `selectedText` | 仅当会话有选中文本时写入 |
| `errorMessage` | 当前主流程基本不传 |
| `audio` | `audioFrames` 拼接后长度大于 0 才写入，采样率固定 16000 |

是否真正保存，由 `App.tsx` 判断：

```ts
onHistoryRecord: (historyInput) => {
  if (!input.saveHistory) {
    return;
  }
  void window.voiceAI.createHistoryRecord(historyInput).catch(...)
}
```

`input.saveHistory` 来自 `settings.privacy.saveHistory`。因此用户选择“从不”后，正常新会话不会调用 `createHistoryRecord()`。

会写入历史的情况：

- 正常完成语音输入，且 `saveHistory === true`。
- 用户取消时已经存在有效会话，且 `saveHistory === true`。
- 用户暂停取消后撤销取消并继续完成处理，且 `saveHistory === true`。

不会写入历史的情况：

- 用户关闭历史保存，也就是 `privacy.historyRetention === "never"` 或 `privacy.saveHistory === false`。
- 语音模块尚未形成有效会话。
- 转写、后处理或插入流程抛错，当前主流程只进入错误状态，不稳定写入 `error` 历史。
- 历史写入本身失败。失败只打日志，不阻塞语音主流程。

状态规则：

| 状态 | 当前写入来源 |
|---|---|
| `completed` | 会话成功结束，且 `finalTranscript.trim()` 非空 |
| `no_audio` | 会话成功结束，但 `finalTranscript.trim()` 为空 |
| `cancelled` | 用户取消已有会话 |
| `error` | 类型和 IPC 校验支持，但当前主流程没有稳定写入 |

### 5.2 本地保存规则

`historyStore.create(input)` 的保存规则：

1. 读取 `index.json`，缺失则当作 `{ records: [] }`。
2. 生成唯一 `id`。
3. 写入音频文件。当前有 32 字节音频加密密钥，所以新音频保存为 `{id}.wav.enc`。
4. 构造 `HistoryRecord`。
5. 插入 `records` 数组，按 `startedAt` 倒序排序。
6. 写回格式化 JSON。

`historyStore.update(id, input)` 的保存规则：

1. 读取 `index.json` 并查找同 `id` 记录。
2. 找不到则抛出 `History record not found`。
3. 保留旧记录的 `id`、`createdAt`、`startedAt`。
4. 用新入参替换 `durationMs`、`mode`、`status`、`transcript`、`finalText`、`selectedText`、`errorMessage`、`audio`。
5. 写回并按 `startedAt` 倒序排序。

音频加密规则：

- 加密算法：AES-256-GCM。
- 文件头魔数：`VHAUD001`。
- 文件结构：`magic + iv + authTag + encryptedData`。
- 密钥长度：32 字节。
- 密钥配置键：`history.audioEncryptionKey`。
- 密钥优先用 Electron `safeStorage` 加密后保存；如果系统安全存储不可用，新密钥以普通 base64 形式保存。
- 读取音频时，若没有加密魔数，按旧版未加密 WAV 读取；若有加密魔数但没有可用密钥，则读取失败。

### 5.3 删除与清理规则

删除单条记录时，必须同时删除索引记录和音频文件。清空或按周期清理时，流程是：

1. 从 `index.json` 找出要删除的记录。
2. 对每条记录的 `audio.path` 执行 `rm(..., { force: true })`。
3. 从 `records` 数组移除记录。
4. 写回新的 `index.json`。
5. 向所有窗口广播删除事件。

清理动作只在这些入口发生：

| 触发入口 | 方法 |
|---|---|
| 历史列表加载前 | `listHistoryRecords()` -> `pruneExpiredHistoryRecords()` |
| 新历史创建后 | `createHistoryRecord()` -> `pruneExpiredHistoryRecords()` |
| 历史重试更新后 | `updateHistoryRecord()` -> `pruneExpiredHistoryRecords()` |
| 用户修改保留策略后 | `applyHistoryRetention()` -> `deleteHistoryRecordsForRetention()` |

当前没有开机启动清理，也没有后台循环清理。

### 5.4 异常规则

- 历史索引文件缺失：视为空历史。
- 历史索引文件 JSON 损坏：加载失败，页面显示错误。
- 音频文件缺失：下载或重试失败。
- 加密音频缺少密钥：读取失败。
- 删除不存在记录：返回 `deleted: false`，不广播删除事件。
- 重试失败：只提示失败，不覆盖原记录。
- `updateHistoryRecord()` 找不到原记录：主进程抛出 `History record not found`。
- 历史保存失败：语音主流程不回滚，只记录日志。
